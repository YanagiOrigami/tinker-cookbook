**Problem Statement**

For each test case you are given a rooted tree with vertices numbered from `0` to `n‑1`.
Vertex `0` is the root.  
For every vertex `i (1 ≤ i < n)` its direct parent `p_i` satisfies `0 ≤ p_i < i`.

You do not know the tree, but you may ask at most `2·n − 2` questions of the following type:

```
? a b     (1 ≤ a, b < n, a ≠ b)
```

The answer is

* `1` – if vertex `a` lies on the (unique) simple path from the root `0` to vertex `b`;
* `-1` – if vertex `b` lies on the path from the root `0` to vertex `a`;
* `0` – otherwise (neither `a` nor `b` is an ancestor of the other).

After you have determined the whole tree you have to output the array  

`p_1 p_2 … p_{n‑1}`.

The interactor is non‑adaptive, i.e. the hidden tree does not change during the
interaction.

--------------------------------------------------------------------

### Input (for hacks)

The first line contains an integer `t (1 ≤ t ≤ 500)` – the number of test cases.  

For each test case

* the first line contains an integer `n (2 ≤ n ≤ 10^4)` – the number of vertices;
* the second line contains `n‑1` integers `p_1, p_2, …, p_{n‑1}` (`0 ≤ p_i < i`) – the
  parent of each vertex.

It is guaranteed that the sum of `n` over all test cases does not exceed `10^4`.

--------------------------------------------------------------------

### Output

For each test case output a line

```
! p_1 p_2 … p_{n‑1}
```

exactly as described above.  
The output of each test case must be on a separate line.

--------------------------------------------------------------------

### Constraints

* `2 ≤ n ≤ 10^4`
* total `n` over all test cases ≤ `10^4`
* at most `2·n − 2` questions may be asked for each test case

--------------------------------------------------------------------

### Sample

**Input**
```
2
4
0 0 1
5
0 1 1 3
```

**Output**
```
! 0 0 1
! 0 1 1 3
```

--------------------------------------------------------------------

### Note

In the first test case the hidden tree is

```
0
│
1
│
2
│
3
```

All answers to the possible queries are consistent with the definition above.

--------------------------------------------------------------------

### Interaction (for the original interactive version)

* After reading `n` you may output queries of the form `? a b`.  
  Remember to flush the output after each query.

* The interactor will answer with `1`, `-1` or `0`.

* When you know the whole tree, output the answer prefixed with `!` as described.

* If you exceed the allowed number of queries or ask an invalid query,
  the interactor will answer `-1` and the verdict will be *Wrong Answer*.

--------------------------------------------------------------------

### Task

Design an algorithm that reconstructs the tree using at most `2·n − 2` queries.
The solution must work for the given constraints.
