**Permutation with Prefix‑Minimum and Suffix‑Maximum Constraints**

You are given a string `s = s₁ s₂ … sₙ` of length `n` (`1 ≤ n ≤ 2·10⁵`).  
Each character of `s` is one of

* `L` – the element placed at position `i` must be the **smallest** among the first `i` elements of the permutation;
* `R` – the element placed at position `i` must be the **largest** among the elements from `i` to `n`;
* `B` – the element placed at position `i` must be both the smallest among the first `i` elements **and** the largest among the elements from `i` to `n`;
* `.` – no restriction for this position.

A **permutation** of length `n` is an array `p = [p₁ , p₂ , … , pₙ]` that contains each integer from `1` to `n` exactly once.

For each test case you have to decide whether there exists a permutation `p` that satisfies **all** the constraints described by `s`.

--------------------------------------------------------------------

### Input
The first line contains a single integer `t` (`1 ≤ t ≤ 10⁴`) – the number of test cases.

For each test case:

* a line with an integer `n` (`1 ≤ n ≤ 2·10⁵`);
* a line with a string `s` of length `n` consisting only of characters `L`, `R`, `B` and `.`.

It is guaranteed that the sum of `n` over all test cases does not exceed `2·10⁵`.

### Output
For each test case output `YES` if a suitable permutation exists, otherwise output `NO`.

The answer is case‑insensitive.

--------------------------------------------------------------------

### Example
#### Input
```
5
4
L.R.
5
...B.
3
LRL
6
L.RB..
1
B
```

#### Output
```
YES
YES
YES
NO
YES
```

### Explanation
*Test case 1* – one possible permutation is `[1,4,2,3]`.  
`p₁ = 1` is the smallest among the first element, `p₃ = 2` is the largest among the suffix `3…4`, the other positions have no restrictions.

*Test case 2* – the only `B` is at position `4`. When we reach it only the number `2` is still unused, therefore it can be both the smallest of the prefix `1…4` and the largest of the suffix `4…5`. A valid permutation is `[1,5,3,2,4]`.

*Test case 4* – at position `4` we have `B`. After fixing previous positions we would still have two numbers left, thus no number can simultaneously be the smallest of the prefix and the largest of the suffix – the answer is `NO`.

### Constraints
* `1 ≤ t ≤ 10⁴`
* `1 ≤ n ≤ 2·10⁵`
* `∑ n ≤ 2·10⁵`

### Note
The problem is equivalent to constructing a permutation while always being allowed to take the **currently smallest** unused number (`L`) or the **currently largest** unused number (`R`).  
A `B` forces that at the moment of its processing **exactly one** number is still unused.  

The solution works in linear time per test case.
